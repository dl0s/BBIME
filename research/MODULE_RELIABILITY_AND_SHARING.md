# BBIME 模块可靠性与跨应用数据共享审查

审查日期：2026-10-01。代码基线：0.1.0.9；本轮收敛版本：0.1.0.10。
范围：应用自有双拼输入、解码封装、设置、词库及复用边界。
不是系统输入法注册、原生词库接管或全局按键服务的实施报告。

后续 `0.1.0.11` 的引擎容量池修复、服务/字段会话/原生适配及验证状态见
[阶段 A/B 实施记录](C:/Users/dove1/Documents/BBIME/research/PHASE_AB_IMPLEMENTATION.md)。
下文保留本次初评边界，不覆盖新版设备验收状态。

## 结论

适合作为“接入我们自己应用的输入模块”继续建设，但目前还不是任意应用即插即用的 SDK。
本轮已独立出可复用设置模块并加固若干实际风险；完整编辑会话层仍与测试应用耦合。

| 目标 | 判断 | 本轮是否实现 |
| --- | --- | --- |
| 多个自有 BB10 应用复用自然码解码代码 | 可行，每个进程一个解码器，在指定输入线程使用 | 单实例保护及回归已加入 |
| 多个接入应用读取同一份基础偏好 | 可行，使用获授权的共享目录及版本化快照 | 显式发布/读取接口与设置页已加入；设备双应用验证待做 |
| 复用同一份只读基础词库 | 同 ABI、同引擎及可信来源下可行 | 仍使用包内词库，不加载共享二进制 |
| 多应用同时读写当前 userdict.dat | 不可靠，不应实施 | 明确禁止直接共写 |
| 共享个人词条和词频 | 有条件可行，需要安全交换格式、授权、合并与单写入者 | 未实现 |
| 替换系统词库或让未接入应用透明使用 | 不能由本模块推出 | 未实现 |

建议顺序：偏好共享 -> 可信只读词库版本发布 -> 个人词条交换 -> 必要时评估单写入服务。
不要以 SSH root 或共用二进制文件绕过这些边界。

## 主要发现

### P1：全局解码状态与多实例接口不相容，已加保护

上游 `pinyinime.cpp:33` 的 `matrix_search` 是进程全局变量；
`im_open_decoder()` 会删除已有实例，`im_close_decoder()` 也作用于同一个全局对象。
0.1.0.9 的 `Decoder` 却允许独立构造多个实例。第二次 open 可替换第一个引擎，
其后任意实例析构又可能关闭其他实例正在使用的引擎。

0.1.0.10 增加进程内唯一 owner、路径一致性检查、显式 close/flush、
失败 open 的清理与状态清空。重复打开同一路径幂等，换路径需要先 close。
拒绝词库路径与用户词库路径字符串相同，防止最明显的读写目标混用。

限制仍存在：owner 不是并发锁，封装不支持多线程同时 open/search/choose。
调用方必须在一个指定输入线程串行使用；路径的硬链接等价性也没有全面检查。
多个编辑框应复用一个服务并维护各自会话，而不是各建一个 Decoder。

### P1：当前可写个人词库不能跨进程共写，未解决为共享功能

`userdict.cpp:61` 的互斥量和更新时间都是本进程静态变量，没有进程共享属性。
`write_back()` 直接修改同一个文件，再 truncate；
没有跨进程事务、写入版本冲突检测或原子替换。

两个应用会各持有旧内存副本，后写入者可覆盖先写入者的词频或词条。
外加文件锁也不够：锁只能约束写入顺序，不能自动合并已经缓存的旧副本。
此外 `load_dict()` 发现验证失败会尝试 reset 文件，不能把损坏恢复当成无损导入。

保持每应用私有 `data/userdict.dat`。本轮在退入后台时 flush，缩小尚未落盘窗口，
但不宣称解决掉电、磁盘满或上游短写的损坏问题。
`im_flush_cache()` 没有成功返回值，不能据此报告个人学习已可靠持久化。

### P1：上游同步导出路径存在边界错误，当前未调用

`get_sync_lemmas_in_utf16le_string_from_beginning()` 中 `temp` 为 `char16[256]`，
但若干边界表达式使用 `temp + sizeof(temp)`；
512 字节被当成 512 个 char16 元素，超出实际数组终点。
主机编译也给出对应 array-bounds 警告。它是源代码审查发现，不是设备崩溃复现。

当前 `Decoder` 不暴露或调用这个同步入口，所以不能据此断言当前普通输入必然触发漏洞。
但新建个人词库导出功能前，必须修复并单独测试上游同步解析/导出，不能直接开启使用。
本轮未修改 vendor，避免未经全面验证地扩展其同步路径。

### P2：启动与菜单自检改变真实学习状态，已隔离

旧 `inputSelftest()` 虽然隔离正文与诊断写入，仍经 chooseCandidate 调用 im_choose，
可能把合成“你好”“中国”等选择纳入真实用户词频。

新增 `Decoder::choose(index, learn)`。自检总是关闭学习；本地设置也能关闭后续选词学习。
不开启学习时仍提交当前候选，但不调用上游学习接口。
主机验证以合成用户词库逐字节比较确认不学习选词、flush 前后文件不变。
已有学习不会因关闭设置而删除，也仍可能参与候选排序；这不是清空个人词库功能。

### P2：默认设置、运行会话与宿主编辑器耦合，部分收敛

旧版没有独立偏好文件，方案和键盘行为写在 Backend 中；
Backend 同时拥有 TextArea、草稿、撤销、候选、按键状态、生命周期和诊断。
直接拷贝它到新应用可能把宿主字段写入测试草稿、沿用前一编辑框的撤销记录，
或把旧控件的信号作用于新控件。

本轮独立 `ModuleProfile` 和 `ModuleSettings`，只负责偏好校验、私有保存和显式快照交换。
Backend 仍是测试应用适配器，并非已完成的多输入框通用会话组件。
接入其他应用前必须分离编辑适配器、草稿和每字段撤销，
加入可靠的焦点绑定/解绑与密码、数字等字段策略。

### P2：UTF-8 输出和保存错误处理，已加固

旧 `Decoder::utf8()` 分别将 UTF-16 代理对编码为两个三字节序列，
不能形成合法的非 BMP UTF-8。已补成四字节编码，非法孤立代理项使用替代字符。
这只修复编码函数，不意味着上游词库已经支持非 BMP 汉字及其音节消费计数。

草稿写入已检查 fsync 和 rename 失败，错误日志不含正文。
设置采用同目录临时文件、文件 fsync、POSIX rename 后才更新内存；
失败时保留旧设置。没有目录 fsync/备用版本恢复，不能承诺完全掉电持久性。

## 模块边界

推荐拆分职责：

```text
宿主字段类型、焦点、选择范围与权限
    -> 编辑适配器
    -> 每字段 InputSession：编码、候选位置、按键、提交/取消
    -> 进程内串行 Decoder：基础词库和私有学习
    -> ModuleSettings：经过校验的行为偏好
```

已经独立可复用的代码：

- `src/moduleprofile.h`：C++98、无 Qt，固定字段与严格值校验。
- `src/modulesettings.h/.cpp`：QtCore/QNX 文件适配，显式私有路径、发布/导入。
- `src/decoder.h/.cpp`：引擎封装，无 Cascades，仍受上游全局状态约束。
- `src/textpositions.h`：原生索引与 UTF-16 转换，不是完整字素簇分割。

仍由宿主负责：

- 当前输入字段与焦点，切换字段时取消/保留 composition 的策略。
- 禁止密码等敏感字段学习、诊断、导出；不能只依赖用户关闭词频开关。
- 输入长度、提交失败、选区替换、每字段撤销、生命周期以及持久化。
- 当前菜单开关与自建输入总闸；不能从共享文件远程启用输入。
- Cascades、浏览器/WebView 和 Android 各自的编辑适配，不可互相推定兼容。

## 必要设置

菜单中的“设置”打开模块设置页；设置编辑保持自建输入暂停，
关闭设置页不自动开启输入，继续使用右上角按钮恢复。

| 设置 | 默认 | 共享 | 生效规则 |
| --- | --- | --- | --- |
| 启动方案 natural/full/english | natural | 是 | 下一次创建 Backend 时使用，不自动切换当前中英文状态 |
| 中文回切方案 natural/full | natural | 是 | 随中文启动方案保存，用于英文启动后的 Alt+Enter |
| 单按 Shift 切换候选 | 开 | 是 | 暂停时修改，恢复输入后使用 |
| 单按 Shift 移动光标 | 开 | 是 | 暂停时修改，恢复输入后使用 |
| 中文标点替换 | 开 | 是 | 只控制普通标点键；Sym 的显式符号保持所选字符 |
| 本应用词频学习 | 开，沿用旧行为 | 否 | 仅禁止之后的 im_choose 学习，不删除历史 |
| 发布/读取共享设置 | 手动 | 不作为偏好转移 | 每次明确命令，不后台自动读写 |

本地文件为私有 `data/module-settings.ini`，共享文件为获授权目录中的
`shared/documents/BBIME/module-profile.ini`。
共享文件不包括学习授权、正文、剪贴板、光标、候选位置、按键、实时中英文状态、
菜单/输入总闸或词库可执行路径。

固定上限 8192 字节。先有界读取为私有快照，再用 QSettings 解析，
防止仅检查源文件大小后直接解析一个已被替换的大文件。
只接受 schema 1、指定引擎标识和完整白名单字段。
未知字段、缺字段、不支持的版本、非法布尔值及不一致的中文方案整体拒绝。
不执行配置内容，不从配置指定的路径加载二进制词库。

## 跨应用读取

### 公开 API 的边界

QSettings 的进程间协调以“能访问同一个文件”为前提。
相同的组织名/应用名不会使两个沙箱中的私有设置变成一个全局设置。
Qt 官方源码文档说明 INI 后端的 advisory locking 与智能合并条件；
这也不能升级成上游 userdict.dat 的并发契约。

BB10 安装的官方 SDK 描述符文档明确提供 `access_shared` 用户权限。
本版在描述符中请求该权限，仅在用户点发布/读取时操作固定共享设置路径。
读取方应用也需具有该目录访问权限，不能因 BBIME 获授权就自动获得权限。
拒绝授权、目录缺失或文件错误时保留本地设置；不通过 root 提升或改 ACL。

权限面较宽：access_shared 不是一个只授予这个配置文件的精细权限。
本实现自我限制访问范围，但用户仍应知道它增加了应用共享文件访问权限。
企业工作空间、SD 卡路径、不同账户和固件策略需分别实测。

### 最小集成示例

```cpp
// privateFile 必须来自宿主自己的私有目录，不能取自共享配置。
bbime::ModuleSettings settings(privateFile);
settings.load(); // 不存在或非法时保留默认值/已加载值。
const QString shared = bbime::ModuleSettings::sharedPath(false);
if (userConfirmed && sessionIdle && !shared.isEmpty())
    settings.importProfile(shared);
```

读取是复制经过校验的偏好，不是跨进程共享一个 QObject 或内存实例。
默认使用本地副本；本版没有目录监听、自动跟随或逐键读取共享文件。
未来可在启动/恢复前台时根据本应用保存的用户授权读取，但必须延后到会话空闲，
不能在半个音节、符号弹窗或按键尚未释放时改变规则。

当前快照按“一个发布者，多个读取者”使用。
同目录 rename 避免半份文件，但不提供多发布者冲突合并；
多方发布时后写入的整份偏好会获胜。

共享目录不是可信发布者认证边界，其他获授权应用可能修改文件。
路径约束、字段白名单和显式读取可限制行为，但没有数字签名。
不要把密钥、授权、可执行路径或安全字段策略存入这种公开快照。

## 词库共享方案

### 基础词库：优先只读、版本化

现在 `dict_pinyin.dat` 含原生 size_t 和结构布局，ARM32 与主机64不能互换；
本轮打包的 ARM 词库哈希保持：

```text
179311C55AB9B912A07EF040E5A95AF97E704E2248B7B97735F17A3E05D13B67
```

同设备、同引擎、同 ABI 可以共享一份不可变基础词库或各应用缓存副本。
发布新版本应使用新文件名，核对来源、格式、目标 ABI、大小和可信哈希/签名，
验证成功后切换版本；不得原地改写正在解码的旧文件。
从共享文件同时获得字典和其 hash 不能认证来源。
旧引擎解析器会依据文件字段分配内存并使用索引，不能直接接收任意外来二进制。

本版仍只加载包内已知字典，没有开放共享词库路径。
安全共享加载器、回退、动态重开以及词库升级恢复都尚未实现。

跨架构交换应使用可审查的 UTF-8 结构化词条，
再由目标引擎工具链生成目标字典；不把当前 dat 称为通用词库格式。
公开词条、领域词和用户学习数据应分库，保留各自许可证与来源。

### 个人词库：交换词条，或使用单写入服务

轻量路线：各应用保留本地学习，经明确授权导出有限词条，
使用带版本的结构化记录交换：规范拼音、词条、计数、记录 ID、来源和修订号。
导入需要大小/长度限制、去重、幂等、撤销/删除语义和频率合并规则。
不能反复把累计词频相加，也不能将原始输入历史或上下文一起导出。
上游同步入口必须先修复审计；当前没有完成此交换接口。

强一致路线：由一个本地词库服务独占可写数据库，接入应用通过受限协议提交增量。
服务负责事务、鉴权、版本及恢复。GUI 无需为此成为 root；
跨应用 IPC/headless 授权、休眠和冷启动、延迟、故障回退均需另做验证。
无法连接服务时应使用本地只读或私有副本，不依赖电脑 SSH 每次输入。

只有数据共享服务不会使未接入的系统应用自动使用自建输入法。
原生 IMF 个人词库格式、授权和引擎协议没有通过当前模块验证，不应覆盖系统资源。

## 性能与功能局限

- 支持自然码、全拼、英文，不是通用的所有双拼方案实现。
- 自然码最多 32 字母；展开全拼最多 39 字节，候选最多 40，歧义路径最多 8。
- 歧义路径截断会丢弃后续可能的有效解释，多个路径按名次交错，不是跨路径概率重排序。
- 提交前缀后重解码剩余码，缺少完整句级跨提交学习、预测与完整模糊音。
- 使用原生 TextArea Custom，默认 IMF 联想、纠错等不会自动继承。
- 正文编辑按码点/代理对保护，不涵盖组合附加符、旗帜或 ZWJ emoji 的字素簇删除。
- 同步解码在 UI 线程，现有毫秒数不包含按键派发、候选渲染、屏幕刷新或长期内存。
- 主机 Windows/64 位测试不能代替 Q10/32 位的 ABI、文件权限和焦点验收。
- 菜单隐藏/显示总闸与 Sym 单轮逻辑保留；它们不是系统级输入切换。
- 原生长按圆形精细光标浮层仍未实现，不能将普通光标移动称为等价接入。

## 验证与下一阶段闸门

本轮验证状态另见 `module-review-validation-0.1.0.10.json`。

已新增主机回归：设置 schema/白名单/布尔值、失败不修改输出、
解码器失败打开及 ownership 生命周期、不学习时用户字典逐字节不变、
UTF-8 代理对、现有自然码与位置回归、确定性随机输入边界。
ARM 构建保留 BB10 libcpp.so.4 ABI；QML 语法检查不代表设备实际类型加载或布局通过。

应用内新增使用私有临时文件的 SETTINGS 自检：保存、读取、共享快照、
版本错误、未知字段、非法布尔值、超长文件和隐私授权不转移。
键盘自检使用独立临时偏好，覆盖关闭两类 Shift、ASCII 标点和大写输入。
以上设备自检和实际双应用共享都需图标启动后才能验收；没有运行证据时不可标成 PASS。

扩大复用前必须完成：

1. Q10 设置页类型加载、滚动布局及失败提示，拒绝/撤回 access_shared 权限仍能本地输入。
2. 一个发布应用和另一个普通身份应用，分别验证读取、私有副本、错误文件与重启恢复。
3. 休眠、强制终止、磁盘满、连续长输入、重复键和焦点切换测试。
4. 分离宿主正文/草稿/撤销与多字段会话，并加入敏感字段拒绝学习策略。
5. 共享词库先建设可信只读加载和恢复，不开启旧 userdict.dat 共写或未修复同步接口。
